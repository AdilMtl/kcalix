# KC-06 — Spike de leitura local no Galaxy Watch/telefone real

**Status:** pendente

**Resultado observável:** existe uma matriz factual dos records entregues pelo Samsung Health no
aparelho, com origem, IDs, timestamps, qualidade e latência; nenhum dado de saúde saiu do celular.

## Contexto

Documentação diz o que pode ser sincronizado, não o que este aparelho realmente fornecerá. Esta
issue elimina suposições antes de criar schema e ingestão definitivos.

## Dependências

- KC-05 concluída.
- Galaxy Watch 5 pareado e Samsung Health atualizado.
- Compartilhamento Samsung Health -> Health Connect ativado pelo usuário.
- Usuário disponível para produzir atividade real controlada.

## Tipos candidatos e ordem

1. `ExerciseSessionRecord` / `READ_EXERCISE`.
2. `HeartRateRecord` / `READ_HEART_RATE`.
3. `TotalCaloriesBurnedRecord` / `READ_TOTAL_CALORIES_BURNED`.
4. `DistanceRecord` / `READ_DISTANCE`.
5. `WeightRecord` / `READ_WEIGHT`, apenas para inventário.
6. `BodyFatRecord` / `READ_BODY_FAT`, apenas para inventário.

Cada permissão adicional é explicada e solicitada separadamente. Sono/passos não entram neste
spike sem decisão explícita nova.

## Roteiro de dados reais

- registrar um treino de força no Watch/Samsung Health;
- registrar uma caminhada ou corrida com duração/distância;
- quando disponível, medir peso/BIA;
- anotar horário final de cada ação;
- abrir/puxar Samsung Health conforme instrução e medir até aparecer no Health Connect;
- comparar visualmente Samsung Health, Health Connect e preview técnico.

## Reader/preview técnico

- janela inicial de 7 dias;
- paginação completa;
- mostrar somente no dispositivo: record type, `dataOrigin.packageName`, ID abreviado,
  created/modified, início/fim/offset, campos disponíveis e contagem;
- para FC, mostrar resumo calculado e contagem, não despejar amostras na UI/log;
- permitir export apenas de uma matriz redigida sem valores de saúde pessoais, se necessário para
  documentação.

## Não escopo

- qualquer upload de saúde;
- schema definitivo/Edge Function;
- filtro hardcoded Samsung;
- reconciliação ou kcal efetiva;
- fila/background/changes;
- armazenar raw HR fora da memória necessária ao cálculo.

## Matriz de testes

1. Janela vazia e janela com records.
2. Paginação sintética >1.000 via fake/Toolbox.
3. Cada permissão negada/revogada individualmente.
4. Timezone/DST e sessão cruzando meia-noite via dados sintéticos.
5. Mais de uma origem no mesmo intervalo.
6. Força real e cardio real.
7. Latência Watch -> Samsung -> Health Connect.
8. Comparar energia total/ativa disponível antes de decidir o record canônico.
9. Fechar app durante leitura: cancelar/retomar sem persistir saúde.

## Saída obrigatória

Criar `connector/docs/HEALTH_CONNECT_DEVICE_MATRIX.md` com, por tipo:

- disponível sim/não/parcial;
- permissão;
- origem real;
- campos/IDs/timestamps fornecidos;
- latência observada;
- qualidade/limitações;
- decisão `INCLUDE`, `DEFER` ou `DROP`;
- motivo e evidência redigida.

## Definition of Done

- [ ] matriz do aparelho real concluída.
- [ ] exercício/FC/energia/distância possuem decisão factual.
- [ ] peso/BF possuem decisão sem ampliar MVP automaticamente.
- [ ] nenhum dado de saúde foi enviado ou logado.
- [ ] permissões podem ser revogadas sem quebrar o app.
- [ ] spec/PRD/backlog foram corrigidos onde a realidade divergiu.
- [ ] KC-07 pode definir consentimento/allow-list sem adivinhação.
