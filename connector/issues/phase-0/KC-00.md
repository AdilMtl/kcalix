# KC-00 — Fechar decisões e baseline do aparelho

**Status:** pendente

**Resultado observável:** existe um registro de decisões sem placeholders que permite criar o
projeto Android sem renomear pacote, mudar autenticação ou redesenhar a Fase Zero depois.

## Contexto

Algumas escolhas são caras de mudar após instalar o primeiro APK, especialmente
`applicationId`, assinatura e método de login. Esta issue não cria código. Ela remove dúvidas
que afetariam todas as próximas conversas.

## Estado inicial

- Branch: `feature/kcalix-connector`.
- Stack e arquitetura aprovadas nos documentos do conector.
- Nenhuma ferramenta Android instalada e nenhum projeto Android criado.
- Defaults atuais: email/senha, um aparelho, janela futura de 7 dias, M1 exercício/cardio.

## Inputs que o usuário deve fornecer ou confirmar

1. Modelo exato do telefone.
2. Versão Android e One UI.
3. Versão do Samsung Health no telefone e firmware do Watch, se facilmente acessíveis.
4. Login do piloto: email/senha da mesma conta Kcalix.
5. Primeiro piloto: somente o aparelho do proprietário ou até 20 aparelhos.
6. `applicationId`: aceitar `com.kcalix.connector` ou escolher outro antes do primeiro release.
7. Nome visível: `Kcalix Connector`.
8. Confirmar que a Fase Zero pode criar/apagar registros claramente marcados como teste.
9. Confirmar que desconectar e apagar são ações distintas.
10. Escolher local de backup da keystore release; a senha nunca entra no repo/chat.

Informações ainda desconhecidas sobre record types não bloqueiam: KC-06 irá medi-las.

## Escopo

- Criar `connector/docs/DECISIONS.md` com tabela decisão, valor, motivo, data e status.
- Registrar dados do aparelho sem identificadores pessoais desnecessários.
- Confirmar defaults ou substituir explicitamente.
- Registrar quais decisões só podem mudar mediante nova spec.

## Não escopo

- instalar Android Studio;
- criar projeto Gradle;
- pedir senha, token ou credencial ao usuário;
- consultar ou alterar Supabase;
- definir record types com base em memória.

## Decisões irreversíveis ou caras

- `applicationId` após distribuição;
- perda/troca da release key;
- misturar input de teste com tabelas canônicas;
- escolher método de login incompatível com a conta atual.

## Testes e evidências

- Cada input tem valor ou está explicitamente delegado a uma issue posterior.
- Links da spec/PRD apontam para o registro de decisões.
- Busca por `TODO_DECISION` nos documentos retorna vazio para itens da Fase Zero.

Não registrar email completo, credenciais, serial, Android ID ou tokens como evidência.
