# KC-03 — Autenticação Kcalix e diagnóstico de conectividade

**Status:** pendente

**Resultado observável:** o usuário entra com a mesma conta Kcalix, o app mostra sessão válida e
perfil correto, restaura a sessão após reabrir e faz logout apenas do conector.

## Contexto

Autenticação é comprovada antes de criar input manual ou Health Connect. Isso separa erros de
credencial/sessão/rede de erros de ingestão. A sessão contém credenciais sensíveis e deve nascer
com armazenamento seguro, não como protótipo em texto plano.

## Dependências

- KC-02 concluída e app instalável.
- URL Supabase e publishable/anon key atuais disponíveis por configuração de build.
- Conta Kcalix de teste existente; senha é digitada pelo usuário no app, nunca passada ao agente.

## Escopo

- tela de login email/senha;
- estados loading, erro de rede, credencial inválida e sucesso;
- cliente Supabase/HTTP com versões pinadas;
- sessão cifrada AES-GCM com chave não exportável no Android Keystore;
- exclusão do cofre em backup/device transfer;
- refresh/restauração de sessão;
- diagnóstico: internet, Supabase alcançável, JWT válido, usuário/perfil carregado;
- logout local que limpa sessão do conector sem encerrar PWA/outros dispositivos.

## Não escopo

- cadastro, convite ou recuperação de senha;
- OAuth/magic link;
- criar tabela de saúde;
- input manual;
- Health Connect;
- `service_role`, token fixo ou senha em arquivo/CLI.

## Decisões técnicas

- APK contém apenas URL e publishable/anon key, que são identificadores públicos.
- Senha é enviada somente ao endpoint Supabase Auth por HTTPS e não é persistida.
- Access/refresh token persistidos ficam cifrados; não confiar no storage default sem provar
  cifragem.
- `android:usesCleartextTraffic=false`.
- Logs mostram códigos/estado, nunca email completo, JWT, refresh token ou body.
- Diagnóstico pode ler o próprio `profiles` usando RLS; não cria dado novo.

## UX esperada

Após login, a tela Diagnóstico mostra:

```text
Conta Kcalix        Conectada
Supabase            Online
Sessão              Válida
Perfil              Carregado
Health Connect      Ainda não verificado
```

Erros devem dizer “sem internet”, “email ou senha inválidos” ou “sessão expirada”, sem expor
detalhes internos.

## Matriz de testes

1. Login correto e perfil do mesmo usuário.
2. Senha incorreta.
3. Sem rede durante login.
4. Fechar/process kill e reabrir: sessão restaura.
5. Token expirado: refresh automático.
6. Refresh inválido: volta ao login sem loop.
7. Logout local: app limpa sessão; PWA continua autenticada.
8. Backup/restore ou reinstalação: token não é restaurado.
9. Busca em log/arquivos/APK: nenhum segredo/token.

## Evidências

- tabela de casos pass/fail neste packet;
- classe/estratégia de storage documentada no README Android;
- screenshot pode mostrar status, mas deve ocultar email;
- registrar apenas IDs sintéticos em testes automatizados.

## Definition of Done

- [ ] mesma conta Kcalix autentica.
- [ ] perfil correto é carregado sob RLS.
- [ ] sessão cifrada restaura e renova.
- [ ] logout local não afeta PWA.
- [ ] backup/reinstalação não restaura token.
- [ ] nenhum segredo aparece em repo, APK ou logs.
- [ ] build/lint/test Android e build/test PWA passam.
