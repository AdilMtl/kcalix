# KC-01 — Preparar a toolchain Android gratuita no Windows

**Status:** pendente

**Resultado observável:** Claude Code consegue localizar SDK/JDK/ADB e executar ferramentas pelo
PowerShell; usuário consegue abrir um emulador e o telefone aparece autorizado no ADB.

## Contexto

Esta máquina começou sem `java`, `adb`, `sdkmanager`, Gradle ou Android Studio. A instalação é
separada do código para que problemas de licença, PATH, driver ou virtualização não sejam
confundidos com bugs do aplicativo.

## Dependências

- KC-00 concluída.
- Acesso administrativo do usuário para instalar software.
- Espaço em disco e conexão para downloads grandes.
- Telefone e cabo USB disponíveis para a parte física.

## Stack fixada

- Android Studio Quail 2 2026.1.2.
- JBR/JDK 17 embutido.
- Android SDK Platform 36.
- Build Tools 36.0.0.
- Platform Tools, Command-line Tools latest e Emulator.
- AVD Android 16/API 36 com imagem Google Play/Google APIs.

Se a versão estável oficial mudar antes da execução, documentar a diferença e verificar a matriz
AGP/Gradle antes de atualizar; não adotar preview automaticamente.

## Ações do usuário

1. Baixar e instalar Android Studio pelo site oficial.
2. Aceitar licenças do SDK.
3. Instalar os componentes listados no SDK Manager.
4. Habilitar virtualização/Windows Hypervisor se o emulador solicitar.
5. No telefone: habilitar Opções do desenvolvedor e Depuração USB.
6. Instalar driver Samsung somente se o dispositivo não aparecer.
7. Conectar/desbloquear e aceitar o fingerprint RSA.

## Ações do agente

- Descobrir e registrar os caminhos reais do SDK/JBR.
- Validar versões sem alterar configurações globais desnecessárias.
- Criar orientação de PATH apenas se os comandos não puderem usar caminhos explícitos.
- Nunca pedir ou imprimir credenciais.

## Comandos de diagnóstico

```powershell
$AndroidSdkPath = Join-Path $env:LOCALAPPDATA 'Android\Sdk'
& "$AndroidSdkPath\cmdline-tools\latest\bin\sdkmanager.bat" --list
& "$AndroidSdkPath\platform-tools\adb.exe" version
& "$AndroidSdkPath\platform-tools\adb.exe" devices
```

O resultado esperado do telefone é `device`, não `unauthorized`. Um emulador ativo aparece como
`emulator-...`.

## Não escopo

- criar projeto Android;
- instalar Gradle global;
- gerar APK;
- configurar assinatura release;
- instalar Health Connect Toolbox;
- mexer em Supabase/PWA.

## Testes e evidências

- Capturar versões e caminhos em `connector/docs/ENVIRONMENT.md`.
- Registrar nome do AVD, API e tipo de imagem, sem screenshot sensível.
- `adb devices` comprova emulador e/ou aparelho; não versionar serial completo.
- Confirmar custo obrigatório R$ 0 e nenhum cartão cadastrado por esta issue.

não instalar versões aleatórias ou Gradle global como workaround.
