# KC-04 — Vertical slice manual Android → Supabase → PWA

**Status:** pendente

**Resultado observável:** o usuário preenche uma atividade manual no APK, envia, vê o registro
claramente marcado como teste na PWA, reenvia sem duplicar e o apaga sem afetar qualquer dado
normal do Kcalix.

## Por que esta issue existe

Ela comprova o caminho completo antes de Health Connect:

```text
form Android -> JWT -> Edge Function -> RLS/Postgres -> hook PWA -> tela -> delete
```

Quando a leitura real for adicionada, instalação, conta, rede, backend e PWA já estarão
isoladamente validados.

## Dependências

- KC-03 concluída, incluindo sessão segura e perfil.
- Usuário aprovou em KC-00 a criação/exclusão de dados de teste.
- Schema remoto real deve ser inspecionado antes da migration.

## Formulário Android

| Campo | Obrigatório | Regra |
|---|---|---|
| Data/hora | sim | ISO local convertido com offset |
| Tipo | sim | força, caminhada, corrida, bike ou outro |
| Duração | sim | inteiro de 1 a 1.440 minutos |
| Kcal do teste | não | número finito de 0 a 10.000 |
| FC média | não | inteiro de 30 a 240 bpm |
| FC máxima | não | inteiro de 30 a 250 e >= média |
| Distância | não | 0 a 500.000 metros |
| Observação | não | até 280 caracteres |

Botões: `Enviar teste`, `Tentar novamente` quando aplicável e `Limpar formulário`.

## Proveniência obrigatória

- `source_kind = manual_setup`;
- `is_test = true`;
- `client_submission_id` UUID gerado uma vez por tentativa lógica;
- `installation_id` para correlação, nunca autenticação;
- PWA exibe “Dado de teste enviado manualmente pelo Kcalix Connector”.

O registro nunca deve parecer leitura Samsung/Health Connect.

## Modelo de dados mínimo

Migration cria `connector_setup_submissions` isolada:

- `id uuid` PK;
- `user_id uuid` FK `auth.users` cascade;
- `client_submission_id uuid`;
- `installation_id uuid`;
- `occurred_at timestamptz` e `timezone_offset_minutes`;
- `activity_type text` com allow-list;
- `duration_min integer`;
- `kcal numeric`, `avg_hr_bpm integer`, `max_hr_bpm integer`, `distance_m numeric` nullable;
- `note text` nullable;
- `source_kind text default 'manual_setup'` e `is_test boolean default true`;
- `created_at timestamptz`;
- UNIQUE nomeada `(user_id, client_submission_id)`.

O banco também aplica CHECK constraints equivalentes aos limites do formulário; validação apenas
na Edge não é suficiente porque um usuário autenticado pode chamar o Data API diretamente.

RLS: usuário autenticado insere, seleciona e apaga somente os próprios registros; `anon` não
acessa. A Edge usa cliente no contexto RLS do JWT e deriva `user_id` da sessão, nunca do body.
Nenhum `service_role` é necessário.

## Contrato de submissão

Endpoint dedicado: `POST /functions/v1/connector-setup-submit` com `verify_jwt=true`.

Body:

```json
{
  "schemaVersion": 1,
  "clientSubmissionId": "uuid",
  "installationId": "uuid",
  "occurredAt": "ISO-8601",
  "timezoneOffsetMinutes": -180,
  "activityType": "strength",
  "durationMin": 45,
  "kcal": 280,
  "avgHrBpm": 118,
  "maxHrBpm": 154,
  "distanceM": null,
  "note": "Teste manual da Fase Zero"
}
```

O body não aceita `userId`, `sourceKind` ou `isTest`. O servidor fixa a proveniência. Repetir o
mesmo `clientSubmissionId` retorna o mesmo registro/estado, sem duplicar. Validation errors usam
`400/422`; `401` sessão; `409` apenas se o mesmo ID chegar com conteúdo diferente.

## PWA

- Criar hook/serviço; nenhum acesso Supabase direto em componente.
- Rota ou card isolado `Teste do Connector`, acessível apenas autenticado na feature branch.
- Listar data, tipo, duração e opcionais com badge `TESTE` e origem manual.
- Atualização explícita ou refetch após abrir; realtime não é requisito.

- Não inserir em treino, diário, corpo, check-in, Coach ou export canônico nesta fase.

## Matriz de testes

1. Payload mínimo e completo.
2. Cada limite inválido; batch parcial não existe nesta fase.
3. Mesmo ID 2x e 10x: uma linha.
4. Mesmo ID com conteúdo diferente: 409.
5. Sem JWT/JWT inválido: 401.
6. Usuário A não vê/apaga B.
7. Android offline: mostra falha e permite retry com o mesmo ID.
8. Envio online após retry aparece uma vez na PWA.
9. Exclusão remove teste e preserva todas as tabelas canônicas.
10. Logs sem payload, email, token ou source ID.
11. Build/testes Android e PWA.

## Evidências

- Screenshot Android enviado e PWA com badge TESTE.
- Query/teste A/B de RLS.
- Confirmação de zero mudança nas tabelas canônicas.
