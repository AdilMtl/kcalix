# KC-02 — Scaffold, emulador, instalação e atualização

**Status:** pendente

**Resultado observável:** um APK debug mínimo é construído pelo terminal, roda no emulador e no
telefone e uma segunda versão é instalada por cima preservando um valor local de teste.

## Contexto

Esta issue prova o ciclo cotidiano esperado pelo usuário:

```text
Claude Code edita -> Gradle testa/compila -> ADB instala/atualiza -> usuário valida
```

Ela não mistura login, Supabase ou Health Connect. Se falhar, o problema está restrito à base
Android/build/dispositivo.

Tela `Diagnóstico` com:

- nome do app e versão;
- ambiente `debug`;
- botão que incrementa um contador local não sensível;

O contador existe para provar que update por cima preserva estado; não define a persistência
final.

## Escopo

- projeto Compose autônomo;
- Gradle Wrapper versionado;
- `.gitignore` Android seguro;
- unit smoke test e Compose/instrumented smoke quando possível;
- build debug;
- instalação no AVD e telefone;
- aumentar `versionCode`/texto e instalar com `adb install -r`;
- workflow CI por path, sem release signing.

## Não escopo

- login ou rede;
- Health Connect dependency/permissão;
- Room/WorkManager/Keystore;
- APK release;
- migration ou PWA.

## Comandos

Dentro de `connector/android/`:

```powershell
.\gradlew.bat --version
.\gradlew.bat clean lint testDebugUnitTest assembleDebug
.\gradlew.bat connectedDebugAndroidTest
.\gradlew.bat installDebug
```

## Matriz de testes

1. Emulador: instalar limpo, abrir, incrementar contador, fechar/reabrir.
2. Emulador: compilar versão seguinte e atualizar; contador permanece.
3. Emulador: desinstalar/reinstalar; contador limpa.
4. Telefone: repetir instalação e update por cima.
5. Offline: app abre e diagnóstico local funciona.
6. PWA: `npm run build` e testes atuais continuam passando.

## Evidências
